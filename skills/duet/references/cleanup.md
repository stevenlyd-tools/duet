# Task-scoped lifecycle cleanup

Clean up temporary branches belonging to the completed task after a confirmed merge or explicit abandonment. Carry out eligible cleanup automatically under the task's existing authorization; do not repeat an approval question for safe cleanup. Age, a closed PR, a naming prefix, or `git branch --merged` alone does not establish eligibility. Never sweep the whole repository. No daemon, timer, new permissions, or cleanup configuration is required.

## Select scope and finish the audit

At task completion, inspect the task's source branches, worktrees and predecessor PRs as one cleanup scope. When the user asks whether old branches/worktrees need cleanup, inspect the named repository or repositories established by the conversation. Inventory local and remote refs, registered worktrees and relevant PRs with complete pagination. A question asking for an inventory does not itself abandon unfinished work or authorize a repository-wide deletion. If the inventory is incomplete, say which part remains unknown.

Review candidates individually against the evidence below. Clean up eligible completed-task artifacts within existing authorization instead of stopping at a list of suggestions. Historical branches outside that authorization remain inventory candidates; do not silently treat age or the current task as permission to remove them. For each candidate, distinguish verified eligible, kept for an identified dependency/active task, blocked by missing evidence/access, and not yet reviewed. Do not describe a count of old or merged branches as a completed cleanup audit.

## Resolve superseded PRs before deleting their branches

A replacement merge does not automatically abandon every predecessor. Read each old PR's scope, discussion, exact head, subsequent commits and links to the replacement. Verify that the replacement covers its entire intended outcome, or that the authorized user explicitly cancelled the remaining scope. An explicit bounded decision to replace the old approach can supply that authorization; do not ask for the same decision again. A similar title, an agent-authored “supersedes” note, or overlap alone is insufficient.

When that authorization and full scope accounting are established, preserve each exact old tip under the recovery rules below before closing an unmerged predecessor PR. Record the replacement link, disposition of remaining work, source tips and recovery location in the existing PR/engineering record within normal communication permissions. Do not close its underlying Issue unless the Issue's own acceptance is satisfied. Recheck that no newer work, active owner, other open PR, selected experiment or rollback depends on the branch. Then close the superseded PR through the provider, verify closure, and apply the normal branch/worktree checks. Do not leave a fully verified, authorized superseded PR open merely because the generic branch rule protects open PRs; resolve the PR first. If scope or authority is missing, retain it and report the smallest unresolved decision.

## Establish eligibility and preserve evidence

1. Follow [freshness](freshness.md), then identify the exact repository, PR, local branch, actual upstream remote/ref, full tips, and task-owned worktree. Inspect `git worktree list --porcelain` and status including untracked files. Identify main, integration/alpha, release branches and repository-protected branches from project/provider rules. Keep these long-lived refs regardless of merge status. If protection or PR status cannot be determined, keep the affected ref and report why.
2. For a merged PR, read the provider's merged state, exact source head and merge commit; confirm the merge commit is on fetched main. Check all open PRs using the proposed head ref (including other base branches); keep a branch still serving an open PR. Local and remote tips must match the reviewed merged source, or their additional work must be separately accounted for. A PR URL or deleted remote branch is not proof that newer local commits were merged. For abandonment, require an explicit task decision; closing an unmerged PR or running `experiment discard` is not permission to lose its history.
3. Before deleting any reference, retain durable handoff, decisions, acceptance/check evidence and issue links in the project's designated records or completed PR. File genuinely deferred work using the tracking convention. Do not delete or close those records as cleanup, and do not manufacture issues for completed work. Records in a removable worktree or ignored coordinator state alone are not durable. Keep secrets and private user data out of published records and recovery uploads.
4. Verify recoverability of each exact tip. An ancestor of durable fetched main is already reachable. For squash/rebase merges, verified PR mapping establishes completion but does not preserve original commits: retain a named local recovery ref such as `refs/duet/archive/<full-tip>` with `git update-ref <archive-ref> <tip> <zero-oid>`, or use an existing durable ref that contains the tip. If the archive ref exists, verify its value rather than overwrite it. Record the recovery ref and repository location with the completion evidence. A SHA in prose, reflog, PR page, or assumed hosting retention alone is not a recovery copy. Do not push recovery history to a new destination without authorization.
5. Keep unpublished unique work and unexplained local/remote differences. For explicitly abandoned work, preserve its committed tip as above before removing the obsolete branch; uncommitted work remains kept. If permanent loss would occur, pause that deletion for specific approval rather than erase it. Preserve originals needed by active dependents, selected checkpoints, current Alpha or rollback; completion of one hardening PR does not retire every experiment it used.

## Remove only eligible references

Operate from a different, safe checkout. Do not modify another active task's checkout, switch its branch, or force-remove a worktree. A clean worktree owned by this completed task can be removed with `git worktree remove <path>` without force, after preserving required ignored files too. If removal refuses, keep it and report the reason; do not add `--force`, reset, stash, or delete directories. Use the host's native archive operation for host-managed worktrees and verify its returned result; do not bypass its attachment/ownership checks. If the current session cannot safely leave its own worktree, keep that local branch and explain the remaining host cleanup step; remote cleanup can still be eligible independently.

Re-read worktrees/status/tips immediately before deletion; no concurrent actor may still own the target. For a local branch no longer checked out, compare-and-delete its exact ref with `git update-ref -d refs/heads/<branch> <expected-local-tip>`. A changed tip fails rather than deleting new commits. Do not blindly retry with the new value. This works for a safely archived squash-merged tip without an unguarded `git branch -D`. Leave unrelated branch configuration alone.

For a remote branch, re-read its actual tip with `git ls-remote --heads <remote> refs/heads/<branch>`. If it differs from the verified tip, keep it. Delete with an explicit expected-value lease, not an unconditional `--delete`:

```text
git push --force-with-lease=refs/heads/<branch>:<expected-remote-tip> <remote> :refs/heads/<branch>
```

These are argument templates: resolve exact names from Git/provider evidence and pass safely quoted arguments; never paste untrusted branch text as shell code. The lease only authorizes deletion of that one verified tip, not rewriting any branch. Recheck provider PR/protection state before pushing. If concurrent use becomes apparent, stop; Git leases protect tip movement, not another person's workflow ownership.

Verify local absence with `git show-ref --verify refs/heads/<branch>` and remote absence with a successful `ls-remote`. Distinguish an absent ref from failed inspection. On a timeout or uncertain push outcome, inspect first; report deleted only after confirmation. If it still exists at the same eligible tip, a retry can follow existing authorization; never retry against a changed tip. Network/access denial keeps the dependent cleanup pending; do not change permissions or erase recovery evidence.

## Remove stale worktree registrations

A missing worktree directory may leave a Git registration that still marks its branch checked out. Inspect `git worktree list --porcelain`, the actual path, lock reason and host ownership. An unavailable mount, moved worktree, host-managed attachment or locked entry is not a deleted directory; restore access or use the host's supported repair/archive operation instead. Never unlock, force-remove or delete administrative directories to make cleanup pass.

For a verified obsolete registration whose directory is gone, first run `git worktree prune --dry-run --verbose --expire now`. Prune is repository-wide, so inspect every proposed removal and proceed with `git worktree prune --verbose --expire now` only when all entries are verified obsolete and within the authorized cleanup scope. Recheck the candidate set immediately before applying; if it includes an unrelated or uncertain entry, defer the prune rather than deleting Git metadata by hand. Re-read the worktree list afterward. Pruning registrations does not delete branch refs; review and remove any eligible local/remote branch separately with the exact-tip checks above.

## Managed coordinator boundaries and report

`experiment discard` and `reconcile` still update coordinator state only; they do not themselves clean up worktrees/branches. Finish reconciliation and dependent/Alpha updates before retiring managed source refs. Never delete `refs/duet/checkpoints/*`, archive refs, coordinator evidence, or current candidate/deployed refs as part of branch cleanup. Keep a managed worktree/ref that active state or a future supported command still requires; do not manually rewrite state to make deletion possible. Ordinary completed PR branches need no coordinator initialization.

Report the repository, completed PR/abandonment decision, verified local/remote tips, durable record and recovery location, actual deleted refs/worktrees, and each kept ref with its specific reason. Partial success is valid: remote deleted/local kept is not complete local cleanup. Failed or uncertain actions retain their exact status. No claim that loading this guidance guarantees automatic execution by every host.

Finish with an explicit disposition for every reviewed candidate: repository/ref/PR, deleted local or remote ref, removed directory versus pruned registration, retained recovery ref and location, or concrete reason kept. Clearly separate unreviewed historical candidates from verified safe ones. A retained active worktree or pending PR is not a cleanup failure; silently dropping it from the report is incomplete accounting.
